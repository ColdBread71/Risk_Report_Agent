# 当前只做一件事：交付能供同事检查的资产清单

更新：2026-09-14。日常从这里读起；业务规则以根目录 `CRA_TARA_workflow_prEN40000.md` 为准。

## 你现在要推进什么

目标是：客户 PDF → 产品范围 → 产品理解 → 尽量完整的资产及保护目标 → 同事反馈。
当前不要求完成风险评分、处置、法规闭合，也不要求你读懂所有 Python 代码。
“所有资产”指在当前评估范围、现有材料和明确假设下尽量列全，不是生成越多越好。

你可以先给同事看标明“待评审”的草稿，不必等 agent 宣布完全正确。草稿要明确缺什么、哪些地方需要他们判断。

## 用四句话理解程序

1. PDF 解析和检索：把材料变成可查的文字，再按问题找相关段落。这是准备工作，不是 Node0 的业务结论。图、表或检索范围不全，后面就可能遗漏。
2. Node0：这次到底评估哪个产品，包含什么，哪些是选配，哪些待确认。
3. Node1：产品做什么、谁使用、怎么连接、有哪些组件和安全功能；另外记录以后评估要使用的方法和接受准则。
4. Node2：这些信息里哪些对象有保护价值，各自要保护什么。资产与保护目标一起输出，暂不判断风险高低。

例如：登录是功能，账户密码是资产，“不能被未授权者读取或使用”是保护目标。三者有关联，但不能用一个“登录服务”概括掉所有凭据、重置密钥和权限配置。
STRIDE 用于后续识别威胁；DREAD 用于后续估计风险。现在不用先学会打分。你提到的 SIRDIE 应是 STRIDE 的拼写。

## 现在怎样看 Excel

先看 Node0 边界是否合理，再看 Node1 功能/组件/通信，最后重点看 Node2。第一遍只问：

- 漏了什么：账户、密码、重置信息、配置、固件、日志、接口、登录/用户管理/更新/运维等是否被考虑？这只是本项目检查起点，不是通用完整目录。
- 写错什么：有没有把选配当标配、支持的能力当已启用、第三方设备当产品内置？
- 合并过头没有：本该分别保护的对象是否挤成一项？反过来也不要把同一对象重复计算。
- 有什么依据：抽查几项关键内容能否在正确 PDF 页找到支持它的正文？引用位置存在不等于结论正确。
- 不知道的有没有说出来：没材料就列待确认，不要猜；缺少证据不等于产品没有该能力。

Node2 表按“资产—目标”关系展开，同一资产可能占多行。资产数量按唯一 ASSET ID 算，不能按 Excel 行数算。PASS/PARTIAL 等模型字段不是人工验收。

第一次交同事的建议条件：产品边界没有明显混淆，关键资产没有已知重大遗漏，关键结论能追溯，其他疑点明确列出。这个条件用于“可供评审”，不代表合规通过。
